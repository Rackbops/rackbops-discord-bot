### Decided — not open for re-planning

**#252 — the preload sweeps only what is provably not in use.**

1. Each run's directory is named `rackbops-bot-test-data-<pid>-<random>` (`mkdtempSync` supplies the random tail; the pid is ours). The sweep removes a sibling directory only when its embedded pid is **not alive**, or the directory is **older than one hour** by mtime (a reused pid cannot hold a run that old), or its name carries **no parseable pid** (the pre-#252 format — a leftover by definition). A directory whose pid is alive and young is left alone: that is the concurrent run the issue describes.
2. Liveness is `process.kill(pid, 0)`: `ESRCH` means dead; `EPERM` means alive but not ours (treated as alive); no throw means alive. Verify on this Windows box that Bun's `process.kill(<pid>, 0)` distinguishes a live from a dead pid before relying on it (a two-line probe; paste it in the PR). If it does not, fall back to age-only sweeping with the hour bound and say so — do not invent a third mechanism.
3. **The logic lives in `test/sweep.ts`**, pure over injected `now`, `isAlive` and the directory listing, so it is unit-testable; the preload calls it with the real ones. The preload's comment says the new bound honestly: accumulation is bounded by liveness and age, not "at one directory".

**#253 — `writeJsonAtomic`'s temp name is unique across containers.**

4. The name gains a per-process random token chosen once at module load: `${path}.${process.pid}.${TMP_TOKEN}.${++tmpCounter}.tmp`, `TMP_TOKEN = randomBytes(4).toString("hex")` from `node:crypto`. The pid stays (it is what a human reads in a leftover); the token is what makes two containers with the same pid and the same counter differ. Not the `wx`-and-retry shape: `Bun.write` has no exclusive flag, and the routing store's `randomUUID` + `wx` (`src/routing/store.ts:180-219`) is the model for a secrets file, which this is not.
5. The composition is one exported pure function, `tmpPathFor(path, pid, token, counter)`, so the guarantee is testable without two processes; `writeJsonAtomic` calls it, pinned by source. The comment above `writeJsonAtomic` (`src/storage.ts:87-98`) and the CONTEXT.md gotcha stop claiming a per-(process, call) name is enough across a handoff and say what is now guaranteed: unique per (process token, call), so two containers cannot share a name; last rename still wins (unchanged, documented). The issue's note about never-swept `*.tmp` leftovers after a crash is out of scope — say so in the plan file.

**#255 — the concurrent-dispose test proves concurrency structurally.**

6. `host.test.ts:766-784` replaces its wall-clock assertion with: start `disposePlugins([a, b, c], log, 500)` without awaiting; each fake `dispose` records its plugin's name in `calls` when invoked; after one turn of the event loop (`await Bun.sleep(0)`), assert `calls` already holds all three names — a sequential implementation has called only `a` by then and cannot call `b` before `a`'s 500 ms timeout, on any machine; then await the call raced against a 5 s hang guard and assert `settled` and the three `running` flags false. No `elapsedMs` anywhere. `timeoutMs` 500 (not 100) so that even a badly starved `Bun.sleep(0)` cannot resume after a sequential loop's first timeout.

## Deviations from the plan (recorded at implementation)

- **The decision-2 probe genuinely ran on this Windows box**, not assumed: `process.kill(process.pid, 0)` does not throw (alive), `process.kill(<a bun -e "1" child's pid, after it exited>, 0)` throws `ESRCH` (dead) — `process.kill(pid, 0)` distinguishes live from dead correctly here, so `isPidAlive` uses the real mechanism, no age-only fallback needed. Probe output is in the PR body; the same property is also pinned as `test/sweep.test.ts`'s `isPidAlive` test (test 7).
- **`sweepStaleTestDirs`'s `opts.tmp` field is accepted but not read by the function body** — the pure decision logic never touches the filesystem (that's what `mtimeOf`/`remove` are for), so `tmp` is carried through only so a caller has everything it used to build those seams in one place; documented in the function's own doc comment so it doesn't read as a forgotten parameter.
- **Two additional tests beyond the plan's numbered 1-10**, both additive, neither replacing anything: `sweepStaleTestDirs`'s "a mix: only the stale ones are removed, the live young one survives" (an integration-style check that the five individual rules compose correctly over one mixed batch) and two extra direct `parsePid` unit tests (a well-formed name, and a completely unrelated name) alongside test 4's pre-#252-format case.
- **A related gap found and documented, not fixed (correctly out of scope):** `src/plugins/index.ts` keeps its own independent copy of the atomic-write pattern (per its own header comment, deliberately not importing `storage.ts`) and still uses the OLD pid+counter-only temp name #253 found insufficient — so `data/plugins/index.json` specifically still has the cross-container collision risk this PR closes for every other `writeJsonAtomic` caller. The CONTEXT.md gotcha now says so explicitly (rather than leaving the old, now-stale "the two must be kept in sync" framing implying they still are), so this doesn't ship as a silent gap. Not fixed here — #253's own scope is `src/storage.ts`'s `writeJsonAtomic` only. Worth a follow-up issue; flagged to the orchestrator rather than filed unilaterally, since no plan step authorized filing one for this bundle.
- No other deviations: all six "Decided" items, all five steps, and all 10 named tests were implemented as specified.
