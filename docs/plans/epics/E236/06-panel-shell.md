## Implementation plan — written by the orchestrating session, to be executed as written

One PR, branch `claude/panel-shell` cut from `origin/main`, in an isolated worktree. Commit this plan as `docs/plans/epics/E236/06-panel-shell.md`.

### Decided — not open for re-planning

- **Re-skin and re-organise only.** No control gains or loses behaviour. No existing test's expectations are edited; if one fails, the change is wrong, not the test.
- **The page script stays inside `ops/admin/public/index.html`.** `server.test.ts` lifts functions out of it between `// NAME:begin` / `// NAME:end` markers (thirteen today: `TIMEOUT_SIGNAL`, `PLUGIN_ADMIN_HELPERS`, `PLUGIN_BADGES`, `PLUGIN_REQUEST_HELPERS`, `PLUGINS_SAVE_PLAN`, `PLUGINS_SAVE`, `PLUGIN_REQUEST_SEND`, `OUTDATED_BANNER_HELPERS`, `RESTART`, `ENV_SCHEMA`, `ENV_SAVE_PLAN`, `ENV_SAVE`, `HAS_ACCESS_SESSION`). The code inside every marked block stays as it is — including the class strings it assigns (`"msg ok"`, `"msg error"`, `"plugin-actions-msg ok"`, `"plugin-actions-msg error"`), which the tests compare exactly.
- **Theme:** `@rackbops/styles`, pinned **exactly** `0.2.39`, the `arcane-obsidian` (dark) / `arcane-parchment` (light) pair, following `prefers-color-scheme`. No toggle. Vendored and committed; no CDN, no build at deploy.
- **Three tabs:** Overview, Plugins, Settings. No Servers tab — it arrives with its own child when it has content.
- **Static assets are an exact-match `Map`**, never a path built from the request.

### Step 1 — the build-only theme package: `ops/admin/theme/`

- `package.json` — `{ "name": "rackbops-bot-admin-theme", "private": true, "type": "module", "scripts": { "build": "bun run build-theme.ts" }, "devDependencies": { "@rackbops/styles": "0.2.39" } }`. Commit its `bun.lock`.
- `build-theme.ts` — exports a pure `composeThemeCss(version: string, obsidian: string, parchment: string): string`: line 1 is the banner
  `/* GENERATED by ops/admin/theme/build-theme.ts from @rackbops/styles@<version> (arcane-obsidian + arcane-parchment). Do not hand-edit: bump the pin in ops/admin/theme/package.json and run "bun run build" there. */`
  followed by the obsidian bundle, then the parchment bundle, LF line endings, one trailing newline. Under `if (import.meta.main)`: read the pin from its own `package.json` and refuse anything that is not an exact `x.y.z`; read `node_modules/@rackbops/styles/package.json` and refuse a version that differs from the pin; read `node_modules/@rackbops/styles/arcane-obsidian/bundle.css` and `…/arcane-parchment/bundle.css` (both verified present in the published 0.2.39 tarball); write `../public/rb-theme.css`. Console output ASCII only.
- `ops/admin/tsconfig.json` includes only `*.ts`; extend `include` to `["*.ts", "theme/*.ts"]` so the new script is typechecked by `ops/admin`'s `bun run check`.
- `README.md` — four lines: what this is, that the output is committed, how to bump (edit the pin, `bun install`, `bun run build`, commit both), and that a test fails if the two disagree.
- Run it; commit `ops/admin/public/rb-theme.css`.

### Step 3 — `ops/admin/public/index.html`

- **Head:** delete the whole `<style>` block. Add `data-rb-style="arcane-obsidian"` to `<html>` as the no-script default; add, before the stylesheets, one inline script that sets `document.documentElement.dataset.rbStyle` to `arcane-obsidian` or `arcane-parchment` from `matchMedia("(prefers-color-scheme: dark)")` and updates on its `change` event; then `<link rel="stylesheet" href="/rb-theme.css">` and `<link rel="stylesheet" href="/admin.css">`.
- **Gate:** same ids and behaviour; wrap in `adm-gate`, input gets `rb-input`, Unlock gets `rb-btn rb-btn--primary`.
- **App:** `<main id="app" class="adm" hidden>` containing, in order: the outdated banner (add `rb-alert rb-alert--danger`, keep the id and `banner-warn`); the header — `<h1 class="rb-wordmark"><span class="rb-wordmark__spark">&#9670;</span>bot admin</h1>`, the instance badge (add `rb-badge rb-badge--md`), `#whoami`, and the `#lock` button moved here from the Status section as `rb-btn rb-btn--ghost`; the tabstrip; three tab panels.
- **Tabstrip:** `<nav aria-label="Sections"><div class="rb-tabstrip" role="tablist">` with three `<button type="button" class="rb-tabstrip__tab" role="tab" id="tab-overview" aria-controls="panel-overview">` (…`plugins`, `settings`). Panels: `<div id="panel-overview" role="tabpanel" aria-labelledby="tab-overview" tabindex="0">`.
  - `panel-overview`: `#status-section`, the Logs section.
  - `panel-plugins`: `#plugins-section`, `#plugin-admin-section`.
  - `panel-settings`: the Config section, `#admins-section`, `#identity-section`.
  Every section keeps its id and gains `class="rb-card"`; section `<h2>`s lose their uppercase treatment (the theme's mono heading voice applies).
- **Classes on static markup and on everything the script builds** (`buildEnvControl`, `buildTagControl`, `populateBranchSelect`, `buildPluginRow`, `buildPluginUpdateBlock`, `loadAdmins`, `renderPluginAdmin`, the logs controls): inputs `rb-input`, selects `rb-select`, textareas `rb-textarea`, labels `rb-label`, checkboxes `rb-checkbox`; buttons `rb-btn`, plus `rb-btn--primary` for the one primary action in a group (Unlock, both Save changes, Add admin, Update now), `rb-btn--danger` for Restart and Remove, `rb-btn--sm` inside plugin and admin rows; `#logs-out` becomes `class="rb-pre rb-log"`. Replace every inline `style="color: var(--muted)"` paragraph with `class="adm-sub"`, and the Lock button's inline background with its new classes. **No legacy custom property may remain anywhere in the file.**
- `makeBadge(text, kind)` — outside the marked blocks — emits `"rb-badge plugin-badge"` plus the old kind class plus its semantic modifier: `active` → `rb-badge--success`, `warn` → `rb-badge--warning`, `update` → `rb-badge--info`. `pluginStateBadge` / `pluginUpdateBadge` (inside `PLUGIN_BADGES`) are untouched.
- **Tabs script — a new marked block** `// TABS:begin` … `// TABS:end` holding two pure functions: `tabFromHash(hash)` → `"overview" | "plugins" | "settings"`, anything else (or empty) → `"overview"`; `nextTabId(current, key)` → the neighbour for `ArrowLeft` / `ArrowRight` (wrapping), first for `Home`, last for `End`, `current` for any other key. Outside the block: `showTab(id, moveFocus)` sets each panel's `hidden`, each tab's `aria-selected`, roving `tabindex` (0 on the open tab, -1 on the others) and `rb-tabstrip__tab--active`, and writes the hash with `history.replaceState`; click, `keydown` and `hashchange` listeners; `showApp()` ends with `showTab(tabFromHash(location.hash), false)`. All five loaders still run at unlock, as today — tabs only show and hide.

### Step 4 — `ops/admin/server.ts`

- `export interface StaticAsset { body: string; contentType: string }`; `HandlerConfig` gains `assets?: ReadonlyMap<string, StaticAsset>`.
- `export const STATIC_ASSET_FILES: Readonly<Record<string, string>> = { "/rb-theme.css": "rb-theme.css", "/admin.css": "admin.css" };`
- In `handleRequest`, directly after the index route: for a `GET`, `config.assets?.get(url.pathname)`; when found, answer it with its `Content-Type` and `Cache-Control: no-cache`. Public at this layer exactly like the page. Everything else falls through unchanged.
- Under `import.meta.main`: build the map by reading each `STATIC_ASSET_FILES` entry from `./public/` with `Bun.file(new URL(…, import.meta.url)).text()`, content type `text/css; charset=utf-8`, and pass it in. No new import, so the Dockerfile COPY ratchet is unaffected and `COPY public ./public` already ships both files.

## Deviations from the plan (recorded when the change was built)

Everything above was executed as written except the following. Each is a "how", not a "what".

- **More marked blocks than the one the plan names.** Besides `TABS` (the two pure functions), `showTab` and the listeners live in `TABS_DOM` (behind `wireTabs(tablist)`), the deferred log scroll in `LOGS_SCROLL`, and `makeBadge`'s modifier mapping in `PLUGIN_BADGE_CLASSES`, so tests can pin them; the thirteen existing blocks are byte-for-byte unchanged. `showTab` finds the tabs and panels by their own ids (never by role), and the `wireTabs` call is null-guarded so a missing tablist can only cost the tabs.
- **The log block scrolls to the newest line even if the admin switched tabs while the load was in flight.** `scrollTop` does nothing on a hidden element, so the jump waits for Overview to be shown (`LOGS_SCROLL`, `afterTabShown`). Without it the tab layout would have changed what "Load" does.
- **`loadStaticAssets(readText)`** is exported from `server.ts` and called by the `import.meta.main` block, so the route-to-file mapping and the `text/css` type are tested rather than only read.
- **Contrast and target-size fixes found by review** that the plan did not name: a plugin state badge's words and the instance badge are body-text colour (the light theme's semantic text colours on their 16% tint are 2.9 / 2.85 / 4.0 : 1); `.plugin-update` sits on `--rb-surface` (danger red on the sunken well is 4.24 : 1); a chip's remove button is at least 24 x 24 px and a plugin bundle's buttons 44px on a phone. The active tab's accent text on its accent wash (4.37 : 1, light theme) is the library's own pairing and is left as is.
- **Styling of a plugin's own bare controls.** Published settings bundles build unclassed `label` / `input` / `select` / `button` elements, so `admin.css` styles them with zero-specificity selectors wholly inside `:where(.plugin-admin-tab …)`.
- **Accessibility details the plan's markup does not spell out:** both wordmark sparks are `aria-hidden="true"` (otherwise the page heading is announced as "◆bot admin"), and the tablist's keydown handler ignores Alt / Ctrl / Meta / Shift combinations (Alt+Left is the browser's Back).
- **`ops/README.md` was edited too**, to list the two new routes (Step 6 names only `CONTEXT.md`).
- **`.kv` and `.adm-hint` were not built** — `.status-grid` and `.field-hint` are styled directly. New helper classes: `.adm-panel`, `.adm-fields`, `.adm-actions`, `.field-hint--danger`, and a restated `[hidden] { display: none !important }` (an author `display` rule otherwise beats `hidden`). `.plugin-name` did not get `rb-label` (it is a name, not a field label). Logs and Config gained ids (`logs-section`, `config-section`).
- **Inline `style=` attributes that are not legacy-variable ones remain** (`width`, two `margin-top`, one `max-width`, and `note.style.marginTop` in `loadPlugins`); the one `notice.style.color = "var(--danger)"` became the `field-hint--danger` class.
- **More tests than Step 5 lists** (every Step 5 name is present and unchanged in meaning): the colour-scheme script, the `[hidden]` rule, the token allowlist and its parser, the class-coverage and class-carrying pins, section-to-tab mapping, gate/banner placement, one tablist, every script-looked-up id, near-miss asset paths, the lifted DOM half of the tabs, the log-scroll deferral, `loadStaticAssets`. `server.test.ts` only gains lines; its imports were added as separate statements so the diff removes none.
- **A URL fragment that is not a tab name opens Overview**, including the old section ids (`#admins-section` ...) that used to scroll to a section. Plan-mandated (`tabFromHash`); nothing in the repo links to them.
- **`/%2e%2e/admin.css` answers 200** because the URL parser resolves the dot segment to exactly `/admin.css` before the handler sees it; every other percent-encoded spelling (`/%72b-theme.css`) is a 404.
